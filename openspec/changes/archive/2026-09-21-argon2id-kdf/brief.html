Argon2id key derivation

TL;DR

After this change, apps can derive a 32-byte key from a password using Argon2id (the modern password-hashing standard) through the existing crypto API — same style as the other WASM crypto functions (hex in, hex out). This is the building block wallet software will need later for stronger encrypted wallets; envelopes and password rules are not part of this change.

What you'll get

  • A new call: crypto.argon2id(passwordHex, saltHex, memoryKiB, iterations, parallelism)
  • Always returns a 32-byte key as 64 lowercase hex characters
  • Works in Node/bundler immediately, and in the browser after init()
  • Safe limits for in-browser WASM (up to 64 MiB memory) covering the planned wallet profiles
  • Tests against known-good Argon2id answers, plus rejection of bad inputs

How it works

Password and salt are passed as hex-encoded bytes (the app encodes UTF-8 itself — no Unicode surprises inside the library). Rust runs Argon2id v1.3 via the maintained RustCrypto crate, compiled into the existing crypto WASM module. No CDN, no threads, no SharedArrayBuffer.

What changes for you

  • New optional API on crypto — existing calls stay the same
  • In a UI, prefer running heavy Argon2 calls in a Worker so the page stays responsive
  • Rebuild WASM after Rust edits as usual (npm run build)

Risks and open questions

  • 64 MiB is a deliberate browser-friendly cap; the RFC’s multi-GiB profiles are out of scope
  • Memory-hard hashing can still hitch the main thread if not offloaded to a Worker
  • Exactly-16-byte salts remain a wallet-envelope rule, not enforced here (primitive allows 8–64)

Out of scope

  • Wallet envelope format / migration
  • Password policy or UI
  • Changes to secretbox
  • Custom Conceal/CryptoNight password KDF
